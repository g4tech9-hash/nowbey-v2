# NowBey — deep-dive audit (2026-10-17)

Blunt version: the concept is strong and some of the engineering is careful. But in the moments NowBey exists for, three things work against residents:

1. **The essential-services page is invisible on phones.** `/open-now` is linked from one desktop hover menu only.
2. **The report flow lies on duplicates.** A "nearby report already covers this" answer shows the user "It is on the map" and throws away what they typed.
3. **Privacy.** The public feed publishes exact pin coordinates next to the reporter's @handle, and the home page tells people to "zoom to the roof".

Around those sit house ads for named businesses inside a hazard product, and several repo documents that overstate what is built (WCAG AAA, offline cache, launch-plan P0s).

## 1. Phase 1 — UX / UI audit

### 1.1 First impressions (5-second test)

**Pass.** The hero reads "What is actually happening, street by street.", the primary action is "Drop a pin", and "No accounts required to read the map" is stated (`src/app/page.tsx`).

**Fail — the hero numbers are wrong (critical trust issue, code-verified).**
- "Open the map · N live": `N` is the count of the latest 40 reports, not all live reports (`page.tsx` L53, L79, L105).
- "Wire stories": `wire` is a `limit(6)` query (`page.tsx` L54, L118), so this stat can never exceed 6.
- "Reports today" is computed from the same 40-row sample.
- A visitor reads these as totals. Fix before anything else on the home page.

**Fail — five names for one action.** "Report" (nav), "Report a spot" (header and empty state), "Drop a pin" (hero), "+ Pin a spot" (map, twice), "Publish to NowBey" (submit). Pick one verb. Recommend **"Report a hazard"**.

**Fail — the "Get the app" page is a developer page.** The footer's "Get the app" goes to `/mobile`, which tells residents to unzip a project, run `npm install`, and use Expo Go. Its main button points to `/downloads/nowbey-expo.zip`, which is not in the repository and no build step creates it (`src/app/mobile/page.tsx` L34).

**Fail — the 260px home map is a billboard.** At zoom 8 with 30 pins, the pins are too close to tap. The UX doc says the same.

### 1.2 Navigation and information architecture

**Good.** Mobile bottom bar has five items: Feed, Map, Report, Wire, Alerts (`nav-links.tsx`).

**Critical — the disaster page is hidden on phones (code-verified).**
- `/open-now` ("What is open now", essential services after disruption) is linked from exactly one place: the desktop hover submenu under "Plans" (`nav-links.tsx` L26).
- The mobile bottom bar drops "Plans" entirely (filter `l.href !== "/support"`), so the child is gone too.
- The footer has only "Plans and pricing". The home page does not link it.
- A phone user during a storm can only reach it by typing the URL.

**Major:**
- The top-level "Plans" link goes to `/support` (pricing). The label hides the disaster page as a child. The labels and destinations don't match.
- The "Plans" submenu opens on hover or focus only (`group-hover`). Touch laptops and tap-only users get the link but no submenu.
- Map filters (category, status) are React state, not URL parameters (`src/app/map/page.tsx` L74). A shared link, a refresh, or Back loses the view. The UX doc's P1.1 is still open.
- Home "Everything" chip and "Clear filters" drop the `status` parameter, while the category chips keep it. Inconsistent.

**Major — the emergency numbers are plain text.** "call 919 / 911" appears only on `/report` (`emergency-notice.tsx`). It is not on home, map or alerts, and it is not a `tel:` link. **Please verify the numbers with the government before changing them.** An older NEMA notice in search results lists different numbers (809-2919 / 376-2042) and is dated 2020. I did not change any numbers.

### 1.3 Usability and friction (core task: the report wizard)

**Critical — a duplicate reads as a fresh success (code-verified).**
- The server correctly detects a nearby duplicate and returns HTTP 200 with `duplicate: true` and the message "A nearby report already covers this event…" (`src/app/api/incidents/route.ts`).
- The wizard ignores the flag and shows "It is on the map — Your report is live for everyone" (`src/app/report/page.tsx` L91).
- Result: the user's headline, details and photo note are discarded, and they believe they published. Nothing tells them an existing report already covers the event.

**Critical — the Publish button gives no reason when disabled (code-verified).** It is disabled when the headline is under 5 characters or there is no pin (`report/page.tsx` L375). The only hint is the placeholder text. The server has the right message ("Give it a headline of at least 5 characters"), but the button never sends.

**Major:**
- **No draft.** Wizard state lives only in memory. Leaving the page, a refresh, or a dropped signal on a phone loses a report that took twenty seconds to write.
- **Photos are replaced by a text line.** "Photo uploads are not available yet." For floods and road damage, the photo is the evidence neighbours trust most. Waze offers a camera icon when reporting; Citizen supports live video.
- **Pin confirmation is off-screen on phones.** Step 3 says "Scroll for the form — a thumbnail of the pin is at the bottom." The user types the headline while the location confirmation is out of view.
- **Jargon in the preview.** "severity 2/4" is shown to residents. Use the four labels they chose.

**Quick:**
- Success copy says "Your report is live for everyone". True, but users are not told that reports go live immediately and are only AI-flagged afterwards. Say what happens and what to do if it is wrong ("Watch this report" is good; add "Edit or remove").

### 1.4 Sign-in and sign-up

**Good.** Live handle-availability check, Google sign-in, plain-language errors ("Enter a valid email address. It is how we help you if you forget your password.").

**Major — "Sign in" lands on the sign-up tab (code-verified).** The header "Sign in" link goes to `/login` with no `mode` parameter. `login-form.tsx` L19 defaults to `signup` unless `mode=signin` is in the URL. A returning user sees "Join your neighbours" with five fields. Fix: default to Sign-in when arriving from the header; keep Sign-up as default only from "Create account".

### 1.5 Alerts

**Good.** Storm alerts reach every subscriber on the free plan (`alerts.ts`, `alerts/page.tsx`). Double opt-in exists. "Stop these alerts" link in every email. Copy is clear about the "3 minute" cap.

**Quick:** under "Waiting for your confirmation email", add "Check your spam folder". Confirmation emails are the most common lost step.

**Major:** "Only near me" stores the exact centre coordinates (see §2.2 privacy).

### 1.6 Map (the interaction most at risk)

**Good (code-verified):** clustering at city zoom (`src/lib/cluster.ts`), unique two-letter category codes with a legend, bounded desktop workspace (`.nb-map-workspace`, which exists in `globals.css`), capped list with "Show more".

**Major:**
- **Pins are not keyboard- or screen-reader accessible.** `NowBeyMap.tsx` has no `role`, `aria-label` or `tabIndex` on markers. The list is the only keyboard route. (UX doc P2.10.)
- **No "locate me" on the browse map.** The report pick step does geolocation; browsing does not. (UX doc P1.2.)
- **Map ↔ list sync is one-way.** Clicking a row flies the map; clicking a pin does not scroll or highlight the row. (UX doc P1.3.)

### 1.7 Accessibility controls

**Major.** Simple view and "Use less data" are in the footer under "Display options" (`app-shell.tsx`). The repo's own CEO document names older users as a priority. These controls should be reachable from the header and offered on first visit.

Simple view itself is well built: 18px base font, 44px targets, decorative imagery off. Keep it; move it.

## 2. Phase 2 — Performance and security

### 2.1 Performance

**Code and build facts:**
- **Nearly every page is server-rendered on demand** (120 dynamic routes), including the home feed (`export const dynamic = "force-dynamic"`). The home page runs four or more DB queries plus badge and engagement lookups on each request, with no revalidation. On a cold serverless database this is the most likely cause of a slow first paint. **Not measured.**
- **Client JavaScript on the home route** is about 66 KB uncompressed in its own route manifest, before shared runtime chunks. Leaflet (~154 KB uncompressed) is lazy-loaded (`ssr: false`). LiveKit (~550 KB uncompressed) is loaded only on `/broadcast`. Code-splitting is working.
- **Default map layer on home and report is "hybrid"** (satellite imagery), the heaviest tiles on first load for mobile-data users on Family Islands.
- **Missing assets.** `src/lib/themes.ts` (L54–58) requests `/scenes/*.jpg` (five photos). There is no `public/` folder. With the default `island` theme these 404 on home, wire, incident, login, you and support, and the page falls back to a dark gradient. `TODO_HUMAN.md` §10 already notes this. The appearance preview also points at a missing file.
- **Polling ignores tab visibility.** Live ticker every 45 s, map every 60 s (`live-ticker.tsx`, `map/page.tsx`). Pause when `document.hidden`.
- **Repeated per-request reads.** `PageScene` calls `getSiteSettings()` on every render. Cache for about 60 s.
- **Layout shift.** Map containers have fixed heights (`h-[260px]`, `min-h-[340px]`), which is good. The stats row and ticker will still shift as data arrives; reserve their height.
- **Skeletons.** Map has one. Live ticker, the alert-profile list and the feed have none.

**Plan to get under 3 seconds (targets, not measurements):**
1. Cache the anonymous home feed for 30–60 s with on-report invalidation.
2. Show a static map preview until tapped; default to the street layer; satellite on request.
3. Fix the missing scene photos or change the default theme (quick win).
4. Pause polling on hidden tabs; cache site settings.
5. Add Lighthouse CI on a preview with a database. Budgets: home LCP under 2.5 s on mid-tier 4G, home route JS under 200 KB compressed. Measure before you claim it.

**Offline — the header is making a false claim.** The status chip says "showing the last cached feed" when offline. There is no service worker that caches data (only `firebase-messaging-sw.js` for push) and no web app manifest. Either build it (service worker, last-feed cache, installable manifest; important for Family Islands) or remove the copy now. The "live" pill reflects `navigator.onLine`, not data freshness. Rename it or make it reflect the last successful refresh.

### 2.2 Security and trust

**Code-verified strengths:**
- The `verified` badge is a staff grant and is not tied to a plan (`src/lib/badges.ts`). The launch plan still lists this as P0; **it is already fixed**. The launch plan is stale.
- Public incident data strips `userId` (`src/lib/public.ts`). Anonymous reports store no account ID.
- The report handle comes from the session, never the request body.
- Headers: `nosniff`, strict referrer policy, Permissions-Policy limiting camera, microphone and geolocation to self, HSTS, and in production `X-Frame-Options: DENY` with `frame-ancestors 'none'` and `form-action 'self'`.
- Payment copy is state-aware ("Payments are not live yet", `support/page.tsx`). The launch plan's P1 is also stale.

**Critical (privacy) — exact location plus handle is public.**
- Public incidents include exact `lat`/`lng` and `authorHandle` (only `userId` is removed).
- The home hero says "zoom to the roof, drag the pin tip to the kerb". The report step says "Zoom to 19 for kerb-level accuracy".
- Together, a resident can pin their own house and link it to their @handle. This is a safety and privacy harm on a platform for neighbours.
- Fix: publish coarse coordinates for resident reports (snap to the nearest street centreline, or add ±50–100 m jitter for residential categories); keep the exact pin for staff; change copy to "pin the road or junction, not a house"; make residential-adjacent categories (flood, water, power) default to anonymous.

**Major (privacy) — alert profiles store exact coordinates.** The "within X km of you" profile saves the precise centre (`wire-forms.tsx` L159–160). Store a rounded centre (two decimal places is about 1 km) or the chosen area only, and disclose it on the privacy page. The launch plan lists Bahamas data-protection compliance as UNVERIFIED. Get counsel.

**Critical (trust) — house ads inside a safety product.** `src/components/ad-slot.tsx` hard-codes four businesses ("Island Fresh 242", "Harbour Marine" selling storm shutters, a beach club, a bookshop). They render labelled "Promoted" on the home rail, the incident detail page, life and support. I could not verify that these businesses are contracted partners. If they are not, this is fabricated endorsement on a safety product. If they are, a shutter advert beside a flood report is tone-deaf. Remove from `/incident`, `/map`, `/alerts`, `/open-now`, and from any feed view that shows an active high-severity report.

**Major (security) — CSP is incomplete.** `next.config.ts` deliberately omits `script-src`, `img-src` and `connect-src`. For a user-generated-content site (reports, comments, Island Life posts), a nonce-based `script-src` is the standard defence in depth. DOMPurify is already a dependency, so the sanitisation side exists.

**Major (security) — report rate limit is per instance.** `src/app/api/incidents/route.ts` L73 uses the in-memory `hit()`. On serverless, every instance has its own counter. The shared limiter `sharedHit()` already exists and is used by forgot-password, reset, and session. Also, 15 reports per hour per IP can lock out a whole mobile-carrier NAT. Use per-account limits for signed-in users and a higher shared IP ceiling for anonymous.

**Minor:** HSTS is `max-age=15552000` (180 days) with no `includeSubDomains`. Raise to one year after confirming all subdomains are HTTPS.

**Trust patterns to adopt (Phase 2 requirement):**
- Every pin shows its source in one line: "Resident report · 3 neighbours confirmed · 12 min ago", or "Official feed", or "Checked by NowBey staff" (open-now already does the last one well).
- Publish step discloses: "Goes live now · AI checks after · you can edit or remove it."
- The pin step shows the privacy rule: "Pin the road, not a house. Only the road is shown publicly."
- Next to the alerts email field: "Only used for alerts. Stop any time."

## 4. Phase 3 — Competitor benchmark and feature discovery

Five benchmarks from adjacent niches, plus two Bahamian players you must plan around. Design patterns are sourced; conversion effects are interpretation, not measured data.

### 4.1 Waze — crowd-sourced road hazards
- **Pattern:** a single report button, category, then subtype; a camera icon to attach a photo ([makeuseof](https://www.makeuseof.com/how-to-report-issues-waze/)); reports stay on the map only for a time that changes with reactions, and "Not there" shortens display time ([Waze Help](https://support.google.com/waze/answer/13739290?hl=en)).
- **Why it converts:** reporting costs one or two taps, and the data decays on its own, so the map stays current without moderators.
- **Adapt:** a "Still there / Gone" one-tap on each pin, with time decay (for example, flood reports fade in two hours unless re-confirmed; road closures last longer). This replaces manual "mark cleared" as the main loop.

### 4.2 Citizen — live incident map and timelines
- **Pattern:** colour-coded active versus resolved incidents on the map, and incident resolution tracking ([App Store](https://apps.apple.com/us/app/citizen-safety-live-video/id1039889567)). Incident cards show update count, number notified and reactions ([Citizen Support](https://support.citizen.com/hc/en-us/articles/34348472620695-Incidents)).
- **Warnings from the same product:** a research case study names deceptive design patterns in the app ([ACM](https://dl.acm.org/doi/fullHtml/10.1145/3544548.3581258)). It notifies users of crimes in progress "before the police respond" ([Google Play](https://play.google.com/store/apps/details?id=sp0n.citizen&hl=en_US)), and prompts users to livestream when close ([Wired](https://www.wired.com/story/citizen/)).
- **Adapt:** the timeline and the active/resolved colour states. Do **not** adopt live video, scanner-style alerts, or prompts that send people toward incidents. That is the reputational trap.

### 4.3 FEMA App — official alerts, multiple places, shelters
- **Pattern:** alerts for up to five locations ([FEMA](https://www.fema.gov/about/news-multimedia/mobile-products)); per-location category toggles ([FEMA Help Center](https://www.fema.gov/about/news-multimedia/mobile-products/app-help-center)); shelter and recovery-centre lists that show "Temporarily Closed" ([App Store](https://apps.apple.com/us/app/fema/id474807486)); a text fallback ("text SHELTER and your ZIP code") for basic phones.
- **Adapt:** a "My places" setup on first run (home, work, family island), with category toggles per place. NowBey already has alert profiles; make them obvious and easy. Show closed states on open-now. Plan an SMS fallback when a sponsor covers cost (the launch docs already rule out SMS until then).

### 4.4 Nextdoor — address verification
- **Pattern:** several verification paths: card, postcard, phone, ID ([Nextdoor Help](https://help.nextdoor.com/s/article/How-to-verify-your-address?language=en_US)).
- **Warning:** a critical analysis says "verified" only means the account is tied to an address, which scammers exploit ([proof.show](https://proof.show/marketplace-scams/neighbor-in-distress-nextdoor)). That is a third-party view, so treat it as a warning, not a fact about Nextdoor.
- **Adapt:** keep NowBey's staff-granted badge. Explain it in one line on the badge ("checked by NowBey staff; does not confirm identity"). Never use "verified resident".

### 4.5 Ushahidi — crowd-sourced crisis mapping
- **Pattern:** reports can be tagged "not verified"; verification by aggregation means mapping unverified reports and checking whether independent sources agree ([CJR](https://www.cjr.org/behind_the_news/the_challenge_of_verifying_cro.php)). Intake works by SMS, email, social and web ([Superscout](https://superscout.co/innovation/ushahidi)).
- **Adapt:** make the difference between "1 report" and "3 neighbours confirmed" visible at a glance. Treat SMS intake as a Family Island strategy when there is funding.

### 4.6 Bahamas News & Emergencies App (BNEA) — the government competitor
- The Government of The Bahamas launched it on 9 October 2025: "emergency alerts, weather warnings and government advisories" for registered citizens ([Bahamas Government](https://www.bahamas.gov.bs/news-press-release/bahamas-news-emergencies-app-launched-to-deliver-news-updates-and-emergency-alerts)). Android users get it from the government website ([Bahamas Local](https://www.bahamaslocal.com/newsitem/339707/Bahamas_News_and_Emergencies_App_Launched_to_Deliver_News_Updates_and_Emergency_Alerts.html)).
- **Implication:** NowBey cannot win on official alerts. It can win on **ground truth**: what neighbours are seeing now, with confirmations and timestamps. Position as the layer beneath official alerts, and link to the official source rather than cloning it.

### 4.7 DRM Authority hub — official preparedness
- Forecasts, alerts, checklists and shelter maps in one hub ([drm.gov.bs](https://drm.gov.bs/)). **Link out**; don't duplicate shelter data without a source.

### 4.8 Bahamas Power and Light — outage reporting
- BPL runs outage reporting and a tracker ([BPL](https://www.bplco.com/services/outages/)). The Tribune reported an island-wide New Providence blackout on 30 July 2026, with BPL asking restored-area customers without power to call its 24-hour centre ([Tribune](https://www.tribune242.com/news/2026/jul/30/island-wide-blackout-after-transformer-explosion-at-blue-hills-power-station/)).
- **Implication:** demand is real, and NowBey already has a "Power" category. Cluster outage pins by street and prompt residents to report to BPL. This is a partnership conversation, not a feature to build alone.

### 4.9 Strategy: adapt, don't clone

Three strategic bets:
1. **Be the neighbour layer under official alerts.** Show an official-alert banner that links to the government source when a warning is active, plus community pins, open-now statuses, and a BPL link during outages.
2. **Self-expiring, re-confirmable reports** ("Still there / Gone" with time decay). This improves data quality and reduces alert noise at the same time.
3. **"My places" onboarding.** Home, work and family island in under a minute, with category toggles per place.

Avoid: live video, scanner feeds, paid safety features, and tab-heavy navigation.
