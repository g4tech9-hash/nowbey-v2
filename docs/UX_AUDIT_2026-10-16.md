# UX audit — 2026-10-16 (lead UX review, whole web app)

Triggered by the production screenshot of `/map` (desktop, signed in as
@mario242): *"pins run the entire length of the page."* Findings are ordered
by user harm. **Fixed** items shipped in this change; **Suggested** items are
deliberately not half-done here and are queued with a concrete next step.

## P0 — Fixed in this change

### 1. Desktop `/map`: the pin list was the page (the reported fault)
The phone layout got a bounded viewport (`nb-fill-view`, <1024px only), but
the desktop grid opted out of every bound:

- grid was `lg:items-start` (columns size to content),
- the rail was `lg:h-auto lg:flex-none`,
- its scroll box was `lg:overflow-visible` (scrolling switched *off*),
- the map was capped at `lg:h-[clamp(420px,68vh,720px)]` and not sticky.

So all ~160 pins laid out in document flow, the page ran for many screens,
and the map scrolled away after the first screenful — on the one page whose
job is "list and map, side by side, at the same time."

**Fix:** `.nb-map-workspace` (globals.css) gives the desktop workspace the
same contract the phone already had — viewport minus sticky header and
`<main>` padding, `min-height: 540px` so short windows scroll instead of
crushing. The grid stretches, the rail is `lg:h-full` with its own
`overflow-y-auto` list, and the map fills its column (`h-full`, clamp
removed). The footer is one short scroll past the workspace, as elsewhere.

### 2. Overlapping pins were unreadable at city zoom
At zoom 14 a dozen Nassau reports share two streets. Every pin rendered as
its own 30px circle, so the centre of the screenshot is a stack of
overlapping discs that cannot be tapped apart.

**Fix:** screen-cell clustering (`src/lib/cluster.ts`, unit-tested). Pins
sharing a ~56px cell become one count badge (e.g. "12") that flies in two
zoom levels per tap; above zoom 16 nothing clusters; the selected pin is
never swallowed by a cluster. The same component serves home, wire,
incident and life maps, so all of them get this.

### 3. Pin letters were ambiguous — and there was no legend
Pins used the first letter of the category label: **S** = Storm *or* Safety,
**F** = Flooding *or* Fire, **N** = Notice (and the default for anything
unknown). No legend existed anywhere, so the map's main visual encoding
could not be decoded at all.

**Fix:** unique two-letter codes per category (`CATEGORIES[].pin` in
geo.ts: FL, ST, PW, WA, SF, RD, MR, FR, HL, TR, EV, NT, AC — uniqueness is
locked by a test), plus a collapsed "What the pins mean" legend in the rail
(colour + code + name, and the cluster badge explained).

### 4. The list itself hid the information it exists for
- Rows showed only a coloured dot (see 3), a truncated title, and
  `{street} · {time} · {n} ✓` — the ✓ and bare count mean nothing to a
  first-time reader. Rows now name the category in its colour, spell out
  "n confirmed", and flag **Dangerous / Blocking** (severity ≥ 3) and
  **Resolved** so the eye lands on what matters.
- Loading was the text "Loading pins…"; now skeleton rows inside the list.
- A failed feed was indistinguishable from an empty island (a 500 with a
  JSON error body rendered "No pins match"). Now: API error bodies throw,
  and the error state has a **Try again** button; a genuinely empty result
  offers **Clear filters**.
- All ~160 rows mounted at once. The rail now windows 40 at a time with
  "Show more pins (n left)", reset whenever filters change.
- Primary filter/island/wire controls were 32–36px tall; they are 40px now.

### 5. Desktop map heading was developer copy
"Aerial streets, street names, your pin to the metre" plus a paragraph
naming Esri/OpenStreetMap/Nominatim and "no API key needed" — vendor trivia
in the largest type on the page. Replaced with the user outcome ("What is
happening, street by street" + how to read/add a pin).

## P1 — Suggested next (not done here)

1. **Filter state is not in the URL on `/map`.** Category/island/wire are
   React state only, so a shared `/map` link, refresh, or Back loses the
   view a neighbour carefully set up. Mirror them into search params
   (`?category=road&parish=…`) the way the home feed already does.
2. **No "near me" or "fit all pins" on the browse map.** Finding your own
   street means search-or-drag. Add a locate button (the pick flow already
   has the Bahamas-bounds geolocation logic) and a fit-bounds action when a
   filter changes.
3. **Map ↔ list sync is one-way and click-only.** Tapping a list row flies
   the map, but tapping a pin only highlights the pin — the list neither
   scrolls to nor highlights its row. Sync `selected` both ways.
4. **60-second silent refresh can move the ground.** `load()` replaces pins
   under an open popup and can reshuffle the list while reading. Keep the
   popup's pin anchored and prefer appending/updating rows in place.
5. **Duplicated primary action.** "Report a spot" (header), "Report"
   (nav), and "+ Pin a spot" (rail, and a phone FAB) are three labels for
   one job on `/map`. Keep the rail/FAB one on the map page; the header CTA
   could step aside there.
6. **"Plans" submenu is hover-only** (`group-hover`, nav-links.tsx). It has
   `focus-within` for keyboards, but touch laptops and tap users get the
   link target only. Open on click too, with `aria-expanded`.

## P2 — Polish / consistency

7. **Type floor:** 66 files use 10–11px text. Much is map chrome/metadata
   where 11px is defensible, but list metadata and feed timestamps should
   settle at 11.5–12px minimum, especially over satellite imagery.
8. **Contrast:** `#4f7a83` on the abyss background (footer-adjacent tertiary
   text, 4 uses) sits below 4.5:1. `#6e97a0` is the floor elsewhere; align.
   **Status (2026-10-17): stale, resolved.** No source file uses `#4f7a83` any
   more, and its light-mode override was removed (Q7 in
   `docs/AUDIT_2026-10-17.md`). Text on the dark surfaces uses the tokens
   above, which pass AA.
9. **Zoom readout** ("zoom 14 · about 35 m across on screen · 8.65 m/px")
   is surveyor language next to the Street View control and overlaps the
   scale bar's corner. Keep the scale bar; move precision readout into the
   pick panel, where it is actionable.
10. **Whole-site:** no skip link existed — keyboard/screen-reader users
    tabbed the full header on every page. **Fixed in this change**
    ("Skip to content" → `#main`). Remaining: Leaflet divIcon markers are
    not keyboard-focusable; the list *is* the keyboard route to pins, which
    makes P1.3 worth doing.
11. **Home map** (`h-[260px]`) shows the whole archipelago at zoom 8 with
    30 pins — pretty, but too small to act on. It works as a billboard;
    label it as one ("Open the map") rather than letting users try to tap
    8px-apart pins. Clustering (P0.2) already improves this.
12. **Expo app** was out of scope here; the same bounded-list and
    unique-code rules should be checked against `expo/app/(tabs)/map.tsx`
    before the next build.
